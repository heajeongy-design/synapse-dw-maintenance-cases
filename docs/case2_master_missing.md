# 케이스 2. 제품 마스터 누락 → 매출 분류 불일치

형식: 증상 → 추적 → 근본 원인 → 조치 → 결과 → 재발 방지

## 배경: 시장 매출 FCT 가 만들어지는 방식

외부 처방 통계 원본을 그대로 쌓는 것이 아니라, **제품 마스터(기준정보)** 로 성분·ATC 를 붙이고 ATC 로 시장 분류(ItemClassGroup)를 정해 FCT 를 만든다.

```
외부 처방 통계 원본
  → 제품 마스터(stg_product_master) 매핑: Product → Ingredient, ATC
  → ATC → ItemClassGroup
  → 시장 매출 FCT (fct_market_sales)
```

마스터에 제품이 없으면 FCT 에서 그 제품은 정상적으로 분류될 수 없다.

## 증상

월별 데이터 검증 중, 특정 제조사의 한 브랜드(이하 제품X) 금액과 시장 분류가 예상과 맞지 않았다.

## 추적

사용한 쿼리: [`sql/case2_01_trace_and_detect.sql`](../sql/case2_01_trace_and_detect.sql)

1. FCT 에서 해당 제조사·브랜드를 제품·브랜드·ATC·분류별로 집계 → 일부 규격이 예상대로 집계되지 않음.
2. FCT 가 아니라 기준정보를 의심 → 제품 마스터에서 해당 브랜드 조회.

```
제품X 정 규격A → 있음
제품X 정 규격B → 있음
제품X 정 규격C → 있음
제품X 정 규격D → 없음
```

## 근본 원인

FCT 로직이 아니라 **기준정보(제품 마스터) 누락**이었다.

```
마스터에 없음 → Product 매핑 실패 → 성분·ATC 없음 → 시장 분류 결정 불가 → FCT 결과 불일치
```

## 조치

- 누락된 규격을 제품 마스터에 추가했다 (제품·브랜드·제조사·ATC·성분).
- 제품 마스터 재적재 후 시장 매출 FCT 를 다시 생성했다.

## 결과

- 해당 규격이 Product → Ingredient → ATC → ItemClassGroup 으로 정상 매핑되어 월 매출 집계가 맞춰졌다.

## 재현 (로컬, 합성 데이터)

`make repro` → [`results/case2_master_missing.md`](../results/case2_master_missing.md)

- 4개 규격 중 1개를 마스터에서 빼면 그 규격만 브랜드·ATC·분류가 비고, 탐지 쿼리가 정확히 그 제품을 찾는다.
- 마스터 보완 + 재생성 후 분류 없음 금액 0, 전체 금액 합계는 그대로(분류만 바뀜).
- 재현 가정: 원 로직에서 매핑 실패 행이 "분류 없음"으로 남았는지 결과에서 빠졌는지는 확인하지 않았다. 재현은 LEFT JOIN(분류 없음)으로 만들었고, 탐지 쿼리는 어느 경우든 같다.
- 코드: [`repro/case2_master_missing.py`](../repro/case2_master_missing.py), 테스트: [`tests/test_case2.py`](../tests/test_case2.py)

## 재발 방지 (재현 과정에서 작성한 제안 — 실무 적용 아님)

- 월 적재 후 **"원천에는 있고 마스터에는 없는 제품"** 탐지 쿼리를 실행해 0행인지 확인. 금액 순으로 정렬해 영향이 큰 것부터 보완.
- 분류 없음 금액 비율을 월별로 기록.

## 배운 점

- 집계 수치가 틀리면 Fact 로직보다 먼저 **Fact 가 의존하는 기준정보**를 확인해야 할 때가 있다.
- 조인 키가 마스터에 없을 때 결과가 어떻게 되는지(분류 없음 / 누락)를 알고 있어야 증상을 해석할 수 있다.
